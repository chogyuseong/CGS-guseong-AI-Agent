# 안전 설계 (초안, 0단계)

참고 제품 '피클'의 실패 사례는 대부분 **권한 통제**와 **검증 없는 보고**에서 나왔다.
그래서 이 프로젝트는 위험한 행동을 프롬프트로 부탁하지 않고 **서버 코드와 테스트로 막는다.**
2단계가 끝나면 "왜 프롬프트가 아니라 코드로 막았는지"와 "감시 에이전트가 무엇을 보고 무엇을 못 보는지"를 이 문서에 채운다.

## 위험 등급

| 등급 | 뜻 | 예 | 처리 |
| --- | --- | --- | --- |
| READ | 조회만 한다 | 장소 검색, 날씨, 일정 조회 | 자동 실행 |
| INTERNAL | 앱 안에서만 바뀌고 되돌릴 수 있다 | 메모, 할 일, 기억 저장 | 자동 실행 후 기록 |
| EXTERNAL | 앱 밖에 흔적이 남는다 | 캘린더 일정 생성·수정·삭제 | 매번 사용자 승인 |
| FORBIDDEN | 만들지 않는다 | 결제, 전화, 메시지 자동 발송, 비밀번호 입력 | 도구 자체가 없다 |

## 절대 원칙과 막는 위치

| 원칙 | 막는 위치 | 단계 |
| --- | --- | --- |
| 공식 API 도구만. 브라우저 자동화, 크롤링 없음 | 도구 목록 자체 | 전체 |
| 결제, 전화, 발송, 비밀번호·카드 입력 없음 | 도구 목록 자체 | 전체 |
| EXTERNAL은 승인 레코드 없으면 실행 불가 | `agent/approvals.py`의 `execute_approved`가 PermissionError | 2 |
| 스스로 도는 작업은 READ 도구만 | 루프가 origin별로 도구 목록을 거름, schedule/watch Task는 Approval 생성 불가 | 1, 6 |
| 완료 보고는 도구 결과 `ok=true`일 때만 | 시스템 프롬프트 + 도구 결과 형식 | 1 |
| 기억은 사용자가 직접 말한 것만 | `remember`가 서버에서 출처와 외부 내용 사용 여부 검사 | 5 |
| 도구 결과 속 지시문은 데이터 | 외부 내용을 경고문으로 감싸 전달, 감시 에이전트에는 도구 결과를 넣지 않음 | 2, 4 |
| 키와 토큰은 .env와 암호화된 DB 필드에만 | `.gitignore`, Fernet 암호화, 로그와 푸시 본문에 개인 내용 금지 | 0, 3, 4 |
| 감시 에이전트는 승인을 대신하지 않음 | 판정은 배지로만 표시, 승인은 항상 사람 | 2 |

## 0단계에서 이미 적용한 것

- `.env`는 `.gitignore`에 들어 있고, 첫 커밋 전에 `git status`로 확인했다.
- `SECRET_KEY`가 없으면 서버가 뜨지 않는다. `DEBUG` 기본값은 False다.
- 모든 화면은 로그인이 필요하고, 대화는 항상 `user=request.user` 조건으로 가져온다(다른 사람 대화는 404).
- 회원가입 화면이 없다. 계정은 `createsuperuser`로만 만든다.
- CSRF 보호를 유지하고, HTMX 요청에도 CSRF 토큰 헤더가 붙는다.
- 배포(`DEBUG=False`)에서는 세션·CSRF 쿠키가 Secure로 바뀐다. HttpOnly와 SameSite=Lax는 항상 켠다.
- Watch 간격 30분 미만은 DB 제약으로도 막혀 있다.
