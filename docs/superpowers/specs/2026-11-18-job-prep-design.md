# 생활 비서 D 첫 단계: 공고별 취업 준비 — 설계

2026-11-18. 요구사항 밖 기능(생활 비서). 사용자 결정: 범위 (가) 공고 붙여넣기, 경험 원문은 암호화 + 등록 전 안내,
경험 등록 화면은 설정 안 '내 경험' 칸("추천대로 진행").

## 목적
채팅에 채용 공고를 붙여 넣고 "이 회사 준비해 줘"라고 하면, 미리 저장해 둔 내 경험과 맞춰
회사별 준비 결과 카드 하나를 보여 준다: ① 요구 역량 대조 ② 부족한 점 ③ 예상 면접 질문 ④ 자소서 방향 ⑤ 준비 체크리스트.

## 목표 / 하지 않을 것 / 실패로 볼 것
- 목표: 지어낸 요구 사항·경험이 카드에 나오지 않는다(서버가 원문 인용을 검사). 경험 원문은 DB에 평문으로 남지 않는다.
- 하지 않음: 채용 API 연동, 공고 저장·목록, 자소서 전문 대필, 경험 수정(지우고 다시 등록), 자동화(예약·감시)에서 사용.
- 실패: 경험 원문이 messages·steps.output·tasks.message_history·DBOS에 평문으로 남는 것, 연락처·주소가 저장되는 것.

## 접근 방법
- (채택) 영화 C와 같은 모양: 모델이 내용을 짜고, 서버가 근거 인용을 검사해 카드로 돌려준다. 맞춤 판단은 코드로 할 수 없으므로
  모델이 하되, "공고에 있는 말인가"·"내 경험에 있는 말인가"는 서버가 글자로 확인한다.
- (버림) 별도 화면에서 공고를 넣고 앱이 모델을 따로 부르는 방식: 예산 예약·감시·기록 구조를 한 벌 더 만들어야 한다.
- (버림) 채팅으로 경험 등록: 원문이 messages에 평문으로 남아 암호화 결정과 충돌한다.

## 설계
### 저장
- 새 표 `experiences`(id, user_id, title String(60) 평문, body_encrypted Text, created_at/updated_at).
  본문은 `PAYLOAD_ENCRYPTION_KEY`(Fernet, `app.security.payload_cipher`)로 암호화. 키가 없으면 기능 꺼짐(메일과 같은 플래그 방식).
- 제한: 사용자당 10개, 본문 2,000자, 제목 60자(구현 중 조정: list_experiences가 전부를 한 번에 모델에게 주므로 입력 상한 2만 자).
- 연락처·주소 차단: 전화번호·이메일·도로명/지번 주소 모양이 제목·본문에 있으면 저장 거절(어떤 종류인지만 알리고 값은 되풀이하지 않음).

### API (`app/routers/experiences.py`)
- `GET /api/experiences` 목록(id, 제목, 글자 수, 만든 시각. 본문 없음), `GET /api/experiences/{id}` 본문 보기,
  `POST /api/experiences` {title, body}, `DELETE /api/experiences/{id}`. 모두 user_id 조건. 키 없으면 503 안내.

### 도구 (채팅 전용 묶음, 예약·감시에는 없음)
- `list_experiences`(READ): 내 경험 전부(id, 제목, 본문)를 돌려준다. 모델 기록(tasks.message_history)에는 메일처럼 봉해서 저장,
  steps.output에는 개수만. 이 결과를 읽은 문맥에서는 공개 검색·장소·날씨·자동화 생성 도구를 숨긴다(메일과 같은 규칙).
- `show_job_prep`(READ): 인자 = 회사·직무, 요구 사항 목록(공고 원문 인용, 필수/우대), 대조(요구 사항 번호, 경험 id, 경험 원문 인용),
  부족한 점, 예상 질문, 자소서 방향, 체크리스트. 서버 검사: 요구 사항 인용이 최근 사용자 메시지(붙여 넣은 공고)에 있음,
  경험 id가 내 것이고 인용이 그 본문에 있음. 하나라도 틀리면 어느 항목인지 알려 실패(모델이 고쳐 다시 부름).
  통과하면 카드 데이터를 돌려준다. 경험 인용은 100자 이하.
- 데이터 정책: 두 도구 모두 외부 전송 없음(앱 DB·모델만). 결과 등급 user_private.
- 프롬프트 한 줄: 공고 준비 요청이면 list_experiences → show_job_prep. 경험이 없으면 설정의 '내 경험'에서 등록하라고 안내.
  → eval 재실행 필요(비용, 사용자 확인 후).

### 화면
- 설정 화면 '내 경험' 카드: 등록 전 안내(저장 위치: 이 앱 DB에 암호화 / 모델 전송: 채팅에서 공고 준비를 요청할 때만 모델 공급자로 /
  연락처·주소 금지 / 지우는 법 / 답변·카드에 인용된 짧은 부분은 대화 기록에 남고 대화를 지우면 함께 지워짐),
  "안내를 읽었습니다" 체크 후 제목·본문 입력해 등록, 목록과 지우기.
- 채팅 단계 카드: `show_job_prep` 결과를 5칸 카드로(StepTimeline CARD_TOOLS, ExternalContent).

### 문서
DECISIONS, TOOLS, DATA_POLICY(경험 줄), SAFETY(인용 검증), STATUS, 이어하기.

## 남은 것(구현 중 내가 정함)
정규식 세부, 카드 배치, 안내 문구 다듬기, 테스트 구성.
