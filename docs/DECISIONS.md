# 설계 결정 기록

면접 준비용. 결정과 이유를 날짜와 함께 한 줄씩 쌓는다.

## 0단계: 뼈대

- 2026-11-16 · 에이전트 루프를 프레임워크 없이 직접 구현한다 → 승인 게이트와 기록을 루프 안에 코드로 끼워 넣어야 하고, 면접에서 한 줄씩 설명할 수 있어야 해서.
- 2026-11-16 · Django 5.2 LTS로 고정한다(6.x 아님) → 명세가 5.x이고, LTS라 보안 업데이트 기간이 길다.
- 2026-11-16 · DB는 `DATABASE_URL` 하나로 SQLite/PostgreSQL을 바꾼다. 값이 비어 있으면 SQLite → 개발은 설치 없이 바로, 배포는 환경변수만 바꾸면 되게.
- 2026-11-16 · SQLite는 URL이 아니라 경로로 연결한다 → 폴더 이름의 공백과 한글이 URL 해석에서 깨지지 않게. 빈 `DATABASE_URL=`이 DB 설정을 통째로 비우던 버그를 이 과정에서 발견해 테스트로 막았다.
- 2026-11-16 · `SECRET_KEY`가 없으면 서버가 아예 뜨지 않게 한다. `DEBUG` 기본값은 False → 설정을 빠뜨린 배포가 디버그 모드로 열리는 사고를 막기 위해.
- 2026-11-16 · Secure 쿠키는 `DEBUG=False`일 때만 켠다 → 개발 서버(http)에서도 로그인이 되게 하면서 배포에서는 강제.
- 2026-11-16 · 모델 이름(`AGENT_MODEL_*`)과 가격표(`MODEL_PRICES`)는 settings에만 둔다 → 모델이 바뀌어도 코드를 고치지 않게. 가격은 공식 가격표를 보고 사람이 채운다.
- 2026-11-16 · 모든 모델이 `TimeStampedModel`을 상속한다 → 생성·수정 시각은 디버깅과 감사 기록의 기본이라서.
- 2026-11-16 · Task / Step / Approval을 세 테이블로 나눈다 → 요청 1건이 도구를 여러 번 부르고(1:N), 그중 외부 행동만 승인이 필요하므로(1:1) 승인 이력을 따로 남긴다.
- 2026-11-16 · Step, Approval, GuardCheck, UsageLog에는 user 외래키를 두지 않는다 → `task.user`로 찾을 수 있고, 같은 값을 두 번 저장하면 어긋날 수 있어서. (개요의 "모든 모델에 user"와 부딪쳐 사용자에게 확인받음)
- 2026-11-16 · `Step.risk_level`은 registry에서 복사해 저장한다 → 나중에 도구 등급이 바뀌어도 당시 기록은 그대로 남게.
- 2026-11-16 · `Message.task`는 SET_NULL, `Memory.source_message`는 CASCADE → 대화 기록은 Task가 지워져도 남기고, 기억은 근거 메시지가 사라지면 함께 지운다.
- 2026-11-16 · Watch 간격 30분 이상을 폼 검증과 DB CheckConstraint 둘 다로 건다 → 도구나 관리자 화면처럼 폼을 거치지 않는 경로에서도 막기 위해.
- 2026-11-16 · Note, Todo 모델은 `tools` 앱에 둔다 → 명세 디렉터리 구조에 따로 자리가 없고, 이 데이터를 다루는 것이 내부 도구뿐이라서.
- 2026-11-16 · Tailwind는 standalone CLI로 빌드하고 결과 CSS(`static/css/app.css`)를 커밋한다 → Node 없이 쓰고, 실행 파일이 없어도 서버는 바로 뜨게. 실행 파일(`bin/`)은 커밋하지 않는다.
- 2026-11-16 · HTMX는 CDN이 아니라 `static/vendor/`에 버전을 고정해 둔다(2.0.4) → 외부 CDN 장애나 변경에 영향받지 않게.
- 2026-11-16 · 화면 높이는 `dvh`, 하단 여백은 `safe-area-inset-bottom` → 모바일 키보드와 아이폰 홈 바에 입력창과 탭이 가려지지 않게.
- 2026-11-16 · `/settings/`는 `/accounts/` 접두사 없이 연결한다 → 명세의 URL 설계를 그대로 따르기 위해.
