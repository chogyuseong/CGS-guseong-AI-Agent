2. 계정 연결·배포를 재개할 때 참고할 절차
========================================

폰과 브라우저에서 볼 것은 docs/PHONE-CHECK.md에 체크리스트로 모아 두었다. 그 밖에:

(1) Google Cloud 콘솔 (캘린더와 메일을 쓰려면)
    - 사용자 인증 정보 > OAuth 클라이언트 > 승인된 리디렉션 URI에
      http://localhost:3000/api/connections/google/callback 추가(끝에 / 없음)
    - Google Calendar API, Gmail API 사용 설정
    - OAuth 동의 화면 범위에 .../auth/calendar.events.owned 와 .../auth/gmail.readonly 추가,
      테스트 사용자에 본인 계정
    - 이 컴퓨터의 .env GOOGLE_REDIRECT_URI는 위 주소로 이미 바꿔 두었다.
      다른 컴퓨터로 .env를 옮겼다면 그 값이 위 주소인지 확인한다
    - 그다음 앱의 설정 > Google 계정 연결에서 연결하고
      "이번 주 금요일 저녁 7시에 성수동에서 저녁 약속 잡아줘"로 검색 > 승인 카드 > 승인 > 등록 확인

(2) 푸시 알림: 현재 첫 PC에는 VAPID_SUBJECT가 설정돼 있다. 다른 PC에서 비어 있으면
    VAPID_SUBJECT='mailto:본인메일'을 넣고 API를 다시 켠 뒤 docs/PUSH-CHECK.md 절차를 따른다
    (메일 주소가 푸시 서비스로 전송되는 값이라 제가 넣지 않았다)

(3) eval 사례 30개 확정 및 첫 평가 완료. 재평가할 때는 apps/api에서
      uv run python -m evals.run_evals                                    예상 비용만 출력
      uv run python -m evals.run_evals --run --email 이메일 --confirm-cost   실제 실행(약 $0.04~0.07)
    결과 한 줄을 docs/EVALS.md 표에 붙인다. 가장 많이 틀린 유형 3개와 개선 제안은 그 뒤에 한다

(4) 배포 재개 시: Railway(선택지 A) 절차. 현재는 로컬 사용을 유지한다.
    Railway 가입·Hobby 결제·사용량 한도 → 서비스 3개(Postgres, api=apps/api, web=apps/web) → 환경변수 →
    Google 리디렉션 URI 추가 → 계정 만들기 → 폰 확인. 순서와 값은 docs/DEPLOY.md

(5) 정해 주실 것
    - 한 건 삭제(기억)를 확인 없이 바로 지우는 방식이 괜찮은지
    - 예약 작업에 메일 읽기를 허용할지(지금은 막아 둠. "매일 아침 메일 요약" 예약이 안 된다)
    (정리됨: 취소 API는 1단계 보강에서 만들었고, 메모·할 일 조회 뒤 기억 저장 제한은 5단계 보강에서 원문 인용 검증으로
     바꿨다. 다크 모드는 9단계 보강에서 시스템 설정을 따르게 만들었다)

알려진 문제(고치지 않음):
  - 답변 끝에 "구글 캘린더에는 넣지 않은 앱 안의 할 일입니다" 같은 말이 아직 가끔 붙는다
  - (고침 2026-11-19) 실행할 때마다 Anthropic 연결을 새로 만들던 것 → 에이전트마다 하나를 재사용(model_choice.py)
  - Open-Meteo 접속이 첫 PC에서 불안정했다
  - 첫 PC 개발 DB의 e2e@example.com 계정: 6단계 보강 마이그레이션이 예전에 자동으로 만든 브리핑을 껐다.

    - 못 옮겼다면 .env.example을 복사해 값을 다시 채운다.
      꼭 필요한 값: DATABASE_URL, SESSION_SECRET, APP_ORIGIN, ANTHROPIC_API_KEY
      도구별: KAKAO_REST_API_KEY, NAVER_CLIENT_ID/SECRET, GOOGLE_CLIENT_ID/SECRET/REDIRECT_URI,
              TOKEN_ENCRYPTION_KEY, VAPID_PUBLIC_KEY/PRIVATE_KEY/SUBJECT
      (SESSION_SECRET은 새로 만들어도 된다. 로그인이 풀릴 뿐이다.
       TOKEN_ENCRYPTION_KEY를 바꾸면 저장된 Google 연결을 다시 해야 한다.)
    - .env.django는 옮기지 않아도 된다. 필요한 값은 이미 .env에 들어 있다.
    - Django판 형식의 .env(SECRET_KEY, TASK_MAX_STEPS 등)를 옮겼다면 DATABASE_URL, SESSION_SECRET, APP_ORIGIN을
      채우고 모델 이름 앞에 anthropic: 을 붙인다(두 번째 PC에서 이렇게 고쳤다. docs/STATUS.md)

(3) DB 데이터: 옮기지 않는다. 개발용 데이터뿐이라 새로 만든다. 계정은 새 컴퓨터에서 다시 만든다.

(4) Claude Code 설정(선택): 저장소 밖에 있어서 따라오지 않는다.
    같은 방식으로 일하려면 지금 컴퓨터의 아래 파일을 새 컴퓨터의 같은 위치로 복사한다.
      ~/.claude/CLAUDE.md                 팀 리더 규칙, 모델 사용 기준
      ~/.claude/agents/*.md               hard-worker, fable-designer 등
      ~/.claude/settings.json 의 model, effortLevel, fallbackModel, modelSettings
      PowerShell 프로필의 "# Claude 모델 단축키" 블록(cc, ccb, ccd, ccf, ccff, ccq, ccp)
    이전 대화 기록은 옮겨지지 않는다. 그래서 이 파일과 docs/가 기억 역할을 한다.

========================================
5. 처음 한 번 실행
========================================

PowerShell 5.1은 && 가 안 된다. 한 줄씩 실행한다. 모두 저장소 루트 기준.

  pnpm install
  pnpm --dir apps/web install
  cd apps/api
  uv sync
  cd ../..

  (.env를 루트에 둔 뒤)

  pnpm db:up
  pnpm db:migrate
  pnpm api:create-user --email 이메일 --password 비밀번호
  pnpm dev

  브라우저에서 http://localhost:3000 을 열고 로그인한다.
  API 문서는 http://localhost:8000/api/docs

  서버를 처음 켜면 DBOS가 DB에 dbos 스키마를 만든다. 아침 브리핑은 자동화 탭의 '아침 브리핑 설정'에서 켠 뒤에만 생긴다.

========================================
6. 컴퓨터가 바뀌면 달라질 수 있는 것
========================================

- Smart App Control: 지금 컴퓨터는 켜져 있어서 서명 없는 실행 파일이 막혔다.
  그래서 스크립트가 `uv run python -m pytest` 같은 python -m 형태이고,
  Biome은 WASM 스크립트(apps/web/scripts/biome-check.mjs), 비밀번호는 bcrypt,
  Playwright는 설치된 Chrome을 쓴다. 새 컴퓨터가 막지 않더라도 이 방식은 그대로 동작한다.
  바꾸지 않는다.
- 포트: 5432(postgres), 8000(API), 3000(웹). 다른 프로그램이 쓰고 있으면 먼저 확인한다.
- 같은 DB에 API 서버를 두 개 띄우지 않는다(DBOS가 서로의 작업을 복구할 수 있다).
- 폰에서 볼 때: .env의 APP_ORIGIN을 'http://PC의LAN주소:3000'으로 바꾸고 API를 다시 켠다.
  푸시와 마이크는 https가 필요하다(docs/PUSH-CHECK.md의 터널 방법). apps/web/README.md 참고.
- Mac이나 Linux라면: 루트 package.json의 api 스크립트에 있는
  `--loop asyncio:SelectorEventLoop`는 Windows용 설정이다. 그대로 둬도 동작한다.
- AGENTS.md의 "이 PC에서 알아 둘 것"은 지금 컴퓨터 기준이다(uv 경로, 다른 프로젝트 컨테이너,
  D:\Downloads, Open-Meteo 접속 문제). 새 컴퓨터에서 다르면 그 절을 고친다.


========================================
7. 이어서 할 일
========================================

이 파일 첫머리의 ‘다음에 이어 할 일’을 기준으로 시작한다. 새 PC의 설치·실행은 3~6절을 따른다.
명세와 현재 구현은 AGENTS.md, docs/BUILD_SPEC.md, docs/STATUS.md를 보고, 과거 평가 결과는 docs/EVALS.md에서 확인한다.

지켜야 하는 것:
  - 승인을 자동으로 통과시키는 코드는 테스트 밖에 두지 않는다. 감시 에이전트는 승인을 대신하지 않는다.
  - EXTERNAL 도구는 requires_approval과 실행기 검사(executor.begin_execution, 승인 때 고정된 인자로만 실행)를 둘 다 거친다.
  - 예약 작업과 조건 감시에는 READ 도구만 넘긴다.
  - 테스트를 먼저 쓰고 실패를 확인한 뒤 구현한다.
  - 작업 단위가 끝날 때마다 이 파일을 고치고 커밋한 뒤 origin/main에 push한다.
    push 전에 키 값과 이메일이 커밋에 없는지 검사한다. 강제 push와 브랜치 삭제는 확인 후에만.
  - .env 값은 화면, 로그, 다른 파일에 출력하지 않는다.

새 PC에서 이어갈 때 쓸 요청
  “AGENTS.md와 배포-이어하기.txt 첫머리를 읽고 다음 미완료 항목을 진행해. 일반적인 구현과 검증은 추천안으로 진행해.”
