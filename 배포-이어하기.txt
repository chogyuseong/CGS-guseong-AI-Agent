3. 지금 하던 일 / 디자인 규칙
==================================================================
다음 할 일: 5단계(기억). PDF 명세의 5단계 후속 프롬프트대로 진행.
  화면(/memory/)은 반드시 frontend-design 스킬을 불러 아래 디자인 시스템으로 만든다(사용자 지시).

완료된 디자인 시스템 (frontend-design 스킬, 사용자 지시: 앞으로 화면 디자인은 이 스킬에 맡김):
- 컨셉 "결재": 승인 카드를 결재 서류처럼(결재란 요청/승인), 승인된 외부 행동에 붉은 "승인" 인장.
  대담함은 승인 카드와 인장에만, 나머지는 조용하게.
- 색: paper #EEF1F4 / sheet #FFFFFF / ink #1D2733 / indigo #24476B / seal #B8322A / muted #5E6B7A
  다크: paper #12171D / sheet #1B222B / ink #E4E8EE / indigo #8FB3D9 / seal #E0675E / muted #93A0AF
  감시 배지 초록·빨강·회색은 명세대로 유지.
- 글꼴: 제목·승인 문구 Hahmlet(명조), 본문 IBM Plex Sans KR. Pretendard는 일부러 안 씀.
- 에이전트 답은 말풍선 대신 왼쪽 선, 내 메시지는 남색 말풍선. 단계는 세로선+점 타임라인.
- 하단 탭 이모지 → 같은 굵기 선 아이콘(SVG), 활성 탭은 위쪽 막대.
- 움직임은 승인 직후 인장 찍히는 순간 하나만, prefers-reduced-motion 존중.
- 테스트가 확인하는 문구는 유지: 탭 이름(채팅/작업 기록/자동화/기억/설정), "입력값 전체 보기",
  "요청과 다를 수 있습니다. 그래도 진행할까요?", hx-trigger="every 1s", "알림 켜기", "홈 화면에 추가" 등.
- 토큰 정의 위치: static/src/input.css (CSS 변수 + @theme inline). 템플릿은 bg-paper, text-ink, bg-indigo 같은 이름만 쓴다.
- 설정·작업 기록은 카드 반복 대신 "한 장의 지면 + 구분선". 새 화면도 이 원칙을 따른다.
- 화면을 바꾸면 360px 라이트/다크 캡처로 확인하고 커밋.

4. 실행 방법 (Windows PowerShell, 프로젝트 폴더에서)
==================================================================
터미널 1: .venv\Scripts\python manage.py runserver localhost:8000
터미널 2: .venv\Scripts\python manage.py run_worker
브라우저: http://localhost:8000  (Google 연결 때문에 127.0.0.1이 아니라 localhost로 접속)
CSS 수정 후: bin\tailwindcss.exe -i static/src/input.css -o static/css/app.css --minify
  (bin\tailwindcss.exe는 깃에 없음. v4.1.11 tailwindcss-windows-x64.exe를 받아 bin\tailwindcss.exe로 저장)
계정: createsuperuser로 만든 계정 1개 있음(비밀번호는 사용자만 앎)
